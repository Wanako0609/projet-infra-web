================================================================================
ROADMAP - PLATEFORME WEB DE DÉPLOIEMENT D'INFRASTRUCTURES VIRTUELLES
================================================================================

Objectif global (V1) :
Permettre à des utilisateurs authentifiés de concevoir visuellement une
infrastructure informatique (glisser-déposer de modules + liens réseau), de la
déployer de façon isolée via Docker, d'interagir avec chaque brique depuis le
navigateur, et de la sauvegarder / exporter / importer / partager en lecture
seule.

--------------------------------------------------------------------------------
ÉTAPE 2 : FORMAT DE FICHIER DÉDIÉ (EXPORT & IMPORT .ZIP)              [TERMINÉE]
--------------------------------------------------------------------------------
Objectif : Permettre la sauvegarde portable et le partage hors-ligne d'une
infrastructure via une archive .zip déclarative (zéro script exécuté à l'import).

Principe & limite assumée en V1 :
- L'OS et les outils proviennent toujours des images vérifiées du catalogue.
- Seuls la topologie (infra.json), les paramètres structurés (config) et les
  fichiers dédiés (init.sql pour PostgreSQL, dossier /workspace pour les postes
  Linux) sont embarqués dans l'archive .zip.
- Les installations manuelles hors /workspace (ex. apt install à la volée dans
  un conteneur) ne sont pas incluses dans l'export en V1.

Réalisé :
[x] Service d'archive sécurisé (backend/app/services/infra_archive.py) :
    - Export .zip contenant infra.json, configs/<node_id>/..., README.txt et
      un docker-compose.yml indicatif généré côté serveur (pour test local).
    - Import strictement déclaratif : ne lit que infra.json et configs/ (ignore
      tout script .sh ou docker-compose.yml), protection anti-Zip Slip, blocage
      des liens symboliques, lecture plafonnée anti zip-bomb et validation
      Pydantic complète contre le catalogue.
[x] Routes API (backend/app/api/infrastructures.py) :
    - GET /api/infrastructures/{id}/export (propriétaire ou lecture seule)
    - POST /api/infrastructures/import (multipart/form-data + renommage optionnel)
    - Exposition CORS de Content-Disposition dans backend/main.py.
[x] Front-end (js/api.js, js/dashboard.js, pages/dashboard.html) :
    - Helpers apiUpload (FormData) et apiDownload (Blob authentifié par JWT).
    - Boutons Exporter (.zip) sur Mes infrastructures et Partagées avec moi.
    - Formulaire Importer (.zip) sur le tableau de bord.

ÉTAPE 3 : MOTEUR D'ORCHESTRATION DOCKER                               [TERMINÉE]
--------------------------------------------------------------------------------
Objectif : Transformer une définition d'infrastructure en vrais conteneurs
isolés qui communiquent entre eux.

Réalisé :
[x] Images vérifiées & build (docker/) :
    - postgres:15-alpine (image officielle)
    - docker/linux-net/Dockerfile (Alpine + iproute2, iputils, tcpdump, curl,
      bind-tools, netcat-openbsd, postgresql16-client, bash, nano)
    - docker/linux-desktop/Dockerfile (lscr.io/linuxserver/wireshark:latest +
      outils réseau/psql, KasmVNC sur :3000 à la demande)
    - docker/build-images.sh pour préparer toutes les images en une commande
[x] Orchestrateur Docker (backend/app/services/docker_orchestrator.py) :
    - Isolation réseau bridge L2 par infrastructure (infra_<id>_net) avec
      allocation dynamique et recyclage automatique des /24 (10.100..250.1..250.0/24)
    - Résolution DNS interne par node.id + conservation optionnelle du dernier
      octet IP dans le /24 alloué
    - Matérialisation sécurisée de init.sql (:ro) et /workspace (:rw) dans
      backend/.runtime/ (ignoré par Git)
    - Quotas RAM/CPU/PIDs, privileged=False, capabilities ciblées (NET_ADMIN +
      NET_RAW sur les postes Linux), shm_size + seccomp pour KasmVNC, port local
      dynamique sur 127.0.0.1 pour le bureau web
    - Démarrage des modules on_demand (linux_desktop) uniquement à la demande
[x] Routes API (backend/app/api/infrastructures.py) :
    - POST /start, POST /stop, GET /status (propriétaire pour start/stop,
      lecture seule autorisée pour status)
    - POST /nodes/{node_id}/start et /stop (contrôle individuel à la demande)
    - Nettoyage Docker automatique lors de DELETE /infrastructures/{id}
[x] Front-end (pages/dashboard.html + js/dashboard.js) :
    - Boutons Démarrer / Arrêter, panneau d'état Docker en direct (réseau,
      sous-réseau, IP, statut) et démarrage/arrêt par module à la demande.
